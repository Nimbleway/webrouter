# Changelog

All notable changes to WebRouter are recorded here, newest first. Versions
follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html); while on
`0.x`, a breaking change bumps the minor version.

## [0.15.0] - 2026-11-24

### Added

- Vendor catalog: InternetData, with 3 read-only endpoints (IP, AS and domain lookups), written from its own API documentation and called live; its free plan answers without a key.

### Changed

- **Vendors are now data APIs.** The router's methods are renamed: `call_vendor()` is `call_data_api()`, `vendor_request()` is `data_api_request()`, `vendors()` is `data_apis()`, `vendor()` is `data_api()`, `vendor_endpoint()` is `data_api_endpoint()` and `find_vendor_endpoints()` is `find_data_api_endpoints()`; the routers' `vendor_credentials=` is `data_api_credentials=`. The MCP tools are `data_apis`, `data_api_endpoint` and `call_data_api`, and the server's write switch is `WEB_ROUTER_ALLOW_DATA_API_WRITES`. Every old name still works, with a `DeprecationWarning`, until a later release removes it: the methods and the keyword on both routers, the old variable (logged once as a warning at startup instead), and the old MCP tool names, which are no longer listed but still run their new tool when called (the answer carries a `deprecated` note) and still count in `WEB_ROUTER_MCP_TOOLS`. Class names (`Vendor`, `VendorEndpoint`, `VendorResponse`, `VendorSummary`, `VendorNotFoundError`, `VendorWriteRefusedError`), the `vendors` extra, `WEB_ROUTER_VENDOR_CATALOG` and the MCP answers' `vendor` fields are unchanged.
- `prefer="accurate"` now uses the shipped search and answer accuracy scores when `accuracy=` is omitted. Explicit scores replace the shipped set; an empty set is refused. Methods without shipped scores keep their default order. Model routers asked to favor accuracy by a router service also receive the shipped scores.
- Routing preference moves from `WebRouter(prefer=)` to the router (experimental): the new `preferred` router, the model routers and `remote` take `prefer` (`cheap` for cost, `fast` for p90 latency or new `accurate`), and `accurate` ranks by shipped search/answer scores or the scores you pass as `accuracy=`. The record names the preference used.
- `OpenAIJudge` leaves the `gpt-6` family at its default temperature, as it does `gpt-5`: `gpt-6-luna` answers `temperature=0` with a 400.
- A judge failure in an `evaluate()` row reads `the judge failed at synthesis: …` (or `grading`), and the benchmark scans grade one test answer before any search (retried once after 10 s, so a busy model host does not cancel the scan), so a judge that cannot run stops the scan before anything is billed. A subclass of a built-in judge that sets no `name` is labelled by its class, as in `GradingFails(openai):gpt-4o`.
- A judge pointed at another endpoint (`base_url`) adds the host to its label, as in `openai:glm-5@models.example.com`, so its figures never combine with the vendor's own.
- The Oxylabs Web API live data class in `web_router.providers.oxylabs_live_data` is now `OxylabsWebApiLiveDataProvider`; the name `OxylabsLiveDataProvider` moves to `web_router.providers.oxylabs_live_data_any`, which serves `oxylabs` over either API. Code that imports or subclasses the old path needs the new name. Built with no Oxylabs credential, it raises a `ConfigurationError` naming both sets: `OXYLABS_USERNAME` and `OXYLABS_PASSWORD`, or `OXYLABS_WEB_API_KEY`.
- A call on the keyless tier of Nimble, Tavily, Firecrawl or Keenable now reports `cost_usd=0.0` with `cost_source="keyless"` instead of the keyed list price, and a budget settles it to $0.
- Budgets settle each attempt when it ends: a backend's reported cost replaces its estimate, and an attempt refused before it started (a 4xx other than 404 or 410, a connection never made, a missing key) counts nothing. `docs/budgets.mdx` opens with a table of what is counted.
- Default routing: `auto` now gives each backend at most half the time left (the last gets all of it) and skips a backend for 30 s after three timeouts in a row. Opt out with `hop_timeout=False` or `timeout_cooldown=False`; `hop_timeout=4` sets a fixed cap.
- Data API discovery no longer takes "close", "contact", "here", "reverse" or "tomorrow" alone as naming a data API, so an everyday search such as "weather in paris tomorrow" lists none; `close crm`, `here maps`, `reverse contact` and `tomorrow io` still name theirs.

### Deprecated

- The `cheapest_first` router name and `web_router.cheapest_first` are deprecated for one release and will be removed in the following release. Both still work with a `DeprecationWarning`; use `PreferredRouter("cheap")`, or `router="preferred"` with `router_config={"prefer": "cheap"}`.

### Fixed

- A backend whose throttle reports a nan wait no longer stays out of `auto` for the rest of the process: the cooldown falls back to the status's default (10 s for a 429). An infinite wait is still capped at 600 s.
- Vendor catalog: Engagemii's `engagemii.company.search` now requires `limit`, since a search without one returns the default 1,000 records for 1,000 units ($50) at the standard rate (10,000 units with `filters.publicCompanies` `only`), and `engagemii.company.lookup`'s notes say that a second lookup of the same website within 24 hours of a charged one is free.
- `you-mcp` refuses a domain filter with a path (`include_domains=["github.com/python"]`, or the same in `exclude_domains`) instead of dropping the path. You.com matches `site:` and its `exclude_domains` argument on the host alone, checked live: an include of `github.com/python` returned 0 of 10 results under `/python` (`exa-mcp` returned 10 of 10), and an exclude of it dropped every github.com result. The call now raises `UnsupportedParameterError` before anything is sent, and `auto` passes `you-mcp` over for a backend that honors the path. A bare host, with or without a trailing slash, is served as before.
- A browser action on an element that never appeared no longer chains Playwright's original error: the cause is scrubbed of the CDP URL, like every other translated page error.
- The MCP server no longer garbles every result when `WEB_ROUTER_MCP_MAX_CHARS` is `0` or negative. Zero cut each answer to its truncation marker, and a negative value sliced from the end of the text, keeping almost all of it while marking it truncated. Either now falls back to the default, as an unreadable value does.
- Under `auto`, an extract that retried failed URLs no longer discards the pages a later backend read when it echoes each URL in the encoded form it fetched: a non-ASCII host as IDNA (`https://xn--mnchen-3ya.de/a` for `https://münchen.de/a`) or a non-ASCII path percent-encoded (`/caf%C3%A9` for `/café`). With two or more such URLs, none matched the URL asked for, so pages that came back were reported as failed. URLs are now matched in that encoded form too.
- Data API catalog entries that failed when called with their own examples: `austender` (a contract notice that exists), `eurostat` and `osv` (an example on only one of two alternative inputs), `unesco-uis` (an indicator and a country, which the API requires), `cpsc-recalls` (a date range that returns recalls), `ibm-global-catalog` (paths that no longer redirect, since redirects are never followed), `legislation-gov-uk` (its own `Accept` for XML and Atom, where the default JSON one got 406, and search on `/all`, since `/search` only redirects) and `ccmixter` (a `limit`, without which the answer's headers are too large to read). `bankofengland` notes that it answers 403 to many automated clients.
- Exa extract now keeps the page status Exa reports for a URL it could not read (`error.httpStatusCode`) as the failure's `status_code`, and its `error` reads as Exa's tag (`CRAWL_NOT_FOUND`) rather than a dict. A page Exa found gone (404, 410) is now `kind="target"`, as it is from Nimble and SpecStream, so `auto` no longer fetches it again, and bills it, on every later backend. A page the site itself throttled (429, 402) keeps that status on its failure but no longer lends it to the error a call raises when every URL failed, where it read as the backend's own throttle and cooled it down for every call; this held for Nimble and SpecStream too.
- `you-mcp` no longer fails a search that has no hits. You.com answers one with the JSON object and then a plain-text hint (`No results for "{". Issue a new query ...`) in the same content, so `json.loads` raised `Extra data` and the call came back as a `ProviderError` rather than an empty result, as the REST provider returns. A query such as `{`, `[` or a lone backslash hit it. The object is now read and the hint left out.
- The hint that a `.env` holds a missing key now sees the file's first variable when the file starts with a UTF-8 byte order mark, as PowerShell 5's `Set-Content -Encoding utf8` writes it. The mark stuck to the variable's name, so a one-key `.env` gave no hint; the MCP server's loader, through python-dotenv, already read such a file.
- A search no longer fails when a result carries U+2028, U+2029 or U+0085. An event stream's lines were split with `str.splitlines`, which also breaks at those three characters; JSON leaves them unescaped, so a reply holding one in a title or a page's text was cut mid-object. `you-mcp` and `exa-mcp` raised `ProviderError` ("MCP response carried no result payload") for a query that had results, and `auto` moved on to its next backend. Brave's answer stream and an `agentcore` gateway that streams were read the same way. A stream's lines now end only at CR, LF or CRLF.
- `plan()` and `run()` no longer fetch the wrong page for a URL written next to non-ASCII punctuation. A URL in typographic quotes (`“https://x/report”`, as macOS, Word and Slack autocorrect write them) kept its closing quote; one followed by full-width CJK punctuation with no space (`https://x/report，谢谢`) took the rest of the sentence with it; and one in markdown bold (`**https://x**`) kept its stars. Typographic quotes and CJK punctuation now end a URL as an ASCII quote does, and a trailing `*` is dropped like a full stop. A markdown link whose text is itself a URL (`[https://x](https://x/pricing)`) now yields its target as well as its text; the target was swallowed with the `]` and never seen.
- `plan()` and `run()` recognize HTTP(S) URLs with uppercase or mixed-case schemes, preserving the path and query and applying the URL policy as usual.
- Under `auto`, an extract that retried a failed URL on a later backend could return its documents out of the order asked for. A page the first backend echoed under the URL it resolved to was sorted after the retried pages: Nimble and Keenable echo a slash added to a bare host, a redirect followed and a fragment dropped, and Jina the added slash. Each page now sorts by the URL it answers, so the documents come back in the order asked, as the Extract guide says.
- Experimental routing on vendor modes: a backend the router names only in a mode runs in that mode alone, a backend-wide exclusion holds when only its modes are offered, an excluded attempt no longer keeps the router's order under a cost cap, a refused mode under a cap ends with its own error, not a budget skip, a depth or effort is not priced on a backend that runs only in modes, and the decider's reason quotes the score the attempts ranked on.

## [0.14.0] - 2026-11-19

### Added

- `LiveDataBackendChoiceError`, a `ConfigurationError`, for a bare live data source name that several configured backends could serve; `providers` names them, and `provider=` picks one. An `except ConfigurationError` still catches it. The `webrouter` command exits 2 on it, a choice to make, rather than 3, a key missing.
- A `webrouter` command line: `search`, `extract`, `answer`, `research`, `browse`, `live-data sources|source|run` and `providers` as shell commands, each calling the public method with the same validation and routing. stdout is the response as one JSON object, without the backend's `raw` payload unless `--raw` asks for it. A failure leaves stdout empty, prints `{"error": {"type", "message"}}` on stderr and exits 1 when the call failed, 2 when it was refused before anything was sent (a cost cap nothing fits included), and 3 when a key or an extra is missing; Ctrl-C exits 130 with the same envelope. `--max-cost USD` caps a call's estimated cost as `Budget(max_cost_usd=...)` does. Also runs as `python -m web_router.cli`. See [Command line](https://docs.webrouter.net/cli).
- Vendor modes you can pin: `search(provider="exa:exa-instant")`, or the same id as a chain entry, runs Exa in its `instant` search type. Exa, Tavily, Parallel, Linkup, Perplexity, Keenable, You.com, Brave and DeepSeek declare their tiers (`exa-instant`, `tavily-ultra-fast`, `linkup-deep`, ...), contents (`exa-highlights`, `you-full-page-cache`) and flags (`brave-extra-snippets`, `deepseek-content`) on the provider class. A pin can name a depth too (`exa:exa-instant+lite`). The mode is merged into the request body before `provider_options`, and refused with `InvalidParameterError` before anything is sent when the caller set something it would overwrite: a `provider_options` key it writes, another `search_depth`, or an `effort` that writes the same field. A pinned search is priced as its mode: `cost_usd` on the response and the budget's charge. Each search contract lists the wire of every mode under `options.mode` and what a router may pick under `offers`. `benchmarks/providers/modes.json` is gone: a scan setup is the id `provider=` takes (`tavily:tavily-ultra-fast`), and a benchmark scan setup written `tavily:ultra-fast` without `@` no longer reads as a vendor mode; a frozen row from an older scan's bare `tavily:fast` (Tavily's tier then) now prices as the `fast` depth.
- Vendor modes for extract: `extract(urls, provider="tavily:tavily-advanced")`, or the same id in an extract chain, pins a mode through the same parser, merge and refusals as search. Tavily (`tavily-advanced`), Linkup (`linkup-pro`, flag `linkup-render-js`), Oxylabs (`oxylabs-render`), Nimble (`nimble-vx8`, `nimble-vx8-pro`, `nimble-vx10`, `nimble-vx10-pro`, `nimble-max`), Exa (flags `exa-highlights`, `exa-summary`) and Browserbase (flag `browserbase-proxies`) declare theirs, each with a price row (an `unknown` one where the vendor publishes none). A pinned extract is priced per URL at its mode, and a chain retries the URLs one member failed on the next member in that member's own mode. `ExtractRequest` gains `mode`, set by a pin. Each extract contract lists its modes under `options.mode`.
- Vendor modes for answer: `answer(question, provider="linkup:linkup-deep")`, or the same id in an answer chain, pins a mode through the same parser, merge and refusals as search. Exa (`exa-fast`, `exa-pro`, `exa-research`, its `model`), Linkup (`linkup-flash`, `linkup-standard`, `linkup-deep`, its `depth`) and Perplexity (`perplexity-low`, `perplexity-medium`, `perplexity-high`, its `effort`) declare theirs, each with a price row (`unknown` for Exa's, which its pricing page does not split by model, and `token_billed` for Perplexity's). `AnswerRequest` gains `mode`, set by a pin.
- Vendor modes for browse: `browse(task, provider="skyvern:skyvern-2.0")`, `submit_browse` or a browse chain entry pins the agent's model or engine. Browser Use declares a tier per model it prices per step (`browser-use-o3`, `browser-use-gemini-flash-latest`, ..., its `llm`) and Skyvern one per `engine` (`skyvern-2.0`, `skyvern-3.0`, `skyvern-openai-cua`, `skyvern-anthropic-cua`, `skyvern-ui-tars`); none has a price before the task runs, so none runs under a cost cap. `BrowseRequest` gains `mode`, set by a pin.
- Experimental: `route_modes=True` (or a router's own `route_modes` attribute) shows a router each search backend's vendor modes as candidates of their own, such as `search:exa:exa-instant`, each with its own estimated cost and p90. Off by default; the `remote` router opts in only through its `router_config`.
- Experimental: a router can name `RouteDecision.attempts`, candidate ids best first such as `["search:exa:exa-instant", "search:exa:exa-deep", "search:tavily"]`, to run one backend in several vendor modes. A mode the backend refuses (400/422) is not charged and its next mode runs; any other failure stops that backend for the call; the record lists each attempt with its `mode`.
- Experimental: deciders read vendor modes. When modes are shown (`route_modes=True`), a decider's option names each mode and what it does, and a decision that ranks a mode fills `attempts`, ranked by the backend's score times the mode's share of that backend's mode scores. `cheapest_first` orders each mode at its own price. The built-in routers still default to `route_modes=False`.
- Experimental: `router="gemini"`, a built-in router on Google's Gemini Decisions API (`GEMINI_API_KEY`). One request asks which backend and, with `route_modes=True`, which vendor mode; a mode ranks by its backend's probability times its share. Off unless named. `route-eval` scores a router by name with `--router router:<name>`.
- One spelling for a vendor mode, `tool:provider[:mode]`: a mode is a tier, a depth, then flags sorted, joined with `+`, each vendor part spelled with its backend's name (`search:exa:exa-instant+lite`). `web_router.modes` parses it into the canonical spelling whatever the order, refuses an unknown part with `InvalidParameterError`, and still reads the benchmarks' `tavily:ultra-fast@deep`. Price rows say what their mode is (`kind`: tier, content, flag, depth or effort; `depth_assumed`; `adds_usd` on a flag), vendor modes are keyed in the new spelling (`prices.estimate("tavily", "search", "tavily-ultra-fast")`), and the old price key `":ultra-fast"` still answers for this release with a `DeprecationWarning`.
- Octen as a search backend: `search(provider="octen")`, over `POST /search`, reading `OCTEN_API_KEY`. It maps `max_results` (as `count`, at most 100), `include_domains`, `exclude_domains`, `locale` (as `language`, the 18 languages Octen lists; another raises before the call), `recency` (as `time_range`) and `search_depth` `fast` and `deep` (as `full_content`, at Octen's default of 2,048 tokens and at its 100,000 maximum); `lite`, `country` and `effort` raise. A result's content is its page body when one was asked for, otherwise Octen's query-relevant highlight; Octen returns no score. `auto` tries it after the keyless tier, with a key. Written from Octen's OpenAPI spec; not yet verified live. New: `Provider.OCTEN`.
- Keirolabs as a search backend: `search(provider="keirolabs")`, over `POST /api/v2/search/lite`, reading `KEIROLABS_API_KEY` as a Bearer token. It maps `max_results` (as `maxResults`); every other shared option raises. A result is a title, a link and a snippet, which is both its description and its content; `score` is set only when Keirolabs sends a number, and no date is returned. `auto` tries it after the keyless tier, with a key. Verified live on 2026-11-12. New: `Provider.KEIROLABS`.

A preset's key is read once from that vendor's variable and sent only to that vendor's host: naming `OPENAI_API_KEY` or another preset's variable for another `base_url` raises `ConfigurationError`, as does a missing key. They share the `remote` router's transport rules: `https` only (plain `http` to loopback), no credentials, query or fragment in the URL, one request, no retries or redirects, no proxy from the environment, answers of `application/json` under 256 KiB, and failures naming the error class or status and the host, never the URL or key. The record names them `llm(<host>)` and `systemone(<host>)`.
- The built-in `fallback` router (experimental): `WebRouter(router="fallback", router_config={"routers": [...]})` asks a list of routers in order -- each a registered name, a mapping of a `"name"` and that router's config, or a router function or object, sync or async -- until one answers a decision that decides something. A member that times out, raises, answers something other than a decision or answers an empty one is passed over; each keeps its own `timeout_s`, cut to the time left, and the router's own limit is the sum of its members' plus those 20 ms unless `router_config["timeout_s"]` sets it, to more than those 20 ms. When none answers, the call runs on the static order, recorded as `router_empty`, or `router_timeout` when the time ran out first, its members recorded either way, and `fail_on_router_error=True` raises `RouterError` with that code. It stops asking 20 ms before its deadline, so its answer always arrives before the call stops waiting. It sends the prompt to every member it asks, one that times out after receiving it included. The record names it `fallback(<member>, ...)`: a member passed in by its `router_name`, else `custom`, never its import path; `remote` as `remote(<scheme>://<host>)`. Members built by name are closed with it (`close()` and `aclose()`); members passed in are not. See [Chaining routers](https://docs.webrouter.net/smart-routing#chaining-routers).
- `DecisionRecord.members` and `CompositeDecision` (experimental, public): a router that asks other routers may answer with `CompositeDecision`, a `RouteDecision` subclass with `members`, a tuple of the new `DecisionMember` (`name`, `outcome` -- `ok`, `router_timeout`, `router_error`, `router_invalid` or `router_empty` --, `ms`, `counted`), which the decision record copies to `members`, and `timed_out`, set when no member answered because the time ran out (recorded as `router_timeout`). A decision whose members are not `DecisionMember`s, or name more than one as counted, is `router_invalid`. The wire format reads a plain `RouteDecision`, so a router service cannot set them. `CompositeDecision` and `DecisionMember` are exported from `web_router`.
- The MCP server's `WEB_ROUTER_MCP_ROUTER` names any built-in router, such as `fallback`, configured by the new `WEB_ROUTER_MCP_ROUTER_CONFIG`, a JSON object read once from the process environment (experimental). Each `api_key_env` in it, and the default variable of each `llm` or `systemone` preset given no key (such as `DEEPSEEK_API_KEY`), is read from the process environment at startup, before any `.env` file is loaded, and captured as `api_key`, so neither a project's `.env` file, `load_env` nor a later change to the environment supplies or moves a router's key; a preset's variable unset there stops the server, and a vendor's variable named for a router posting to another host is refused; a value that is not a JSON object, or one set beside no built-in router, stops the server without echoing it. The capabilities resource names each router service's scheme and host in `router_note` and `prompt_note`, a preset's included, and `router` names it as the record will (`llm(api.openai.com)`, `remote(https://host)`), and `router_runs` is `built_in` for a router whose config names no URL. `WEB_ROUTER_MCP_ROUTER=remote` without the new variable reads `WEB_ROUTER_REMOTE_ROUTER_URL` as before. See [docs/mcp.md](https://docs.webrouter.net/mcp-server#routing-and-budgets-web_run-budget_start-budget_status).
- `examples/router_openai_decisions.py` (experimental): OpenAI's Decisions API (`gpt-6-luna`, pinned) as a decider on `DeciderRouter`, one `choice` question per call ranked by its probability per option, 3 s. It sends the prompt to OpenAI and bills one call per plan; tested offline.
- A router may declare its own `route_tools` (experimental): an optional attribute on the router function or object, like `timeout_s`, read when the caller passes `route_tools=None`. The caller's `route_tools` always wins, a router that declares none is still asked on all five tools, and `plan()` and `run()` ask the router whatever it declares; a declaration naming anything else raises `ConfigurationError`. A router built by name declares it too: `router="remote"` takes `route_tools` in `router_config`. From `router_latency.py`'s run, the LLM example router declares `("research", "browse")` and the Jev example every tool but search: at a p50 of 1.2 s and 0.24 s they cost more than a quarter of a search, and the LLM router of an answer too; extract, research and browse are judgement, since they take seconds to minutes. The rules and sklearn examples declare none. See [Smart routing](https://docs.webrouter.net/smart-routing).
- `benchmarks/providers/router_latency.py` (experimental): times routers -- the built-in rules, the scikit-learn, LLM and Jev examples, a `remote:<url>` service in the wire format, or your own -- on route-eval's public prompts, interleaved through the library's own router call, with timeouts censored, cold first calls and fresh builds apart, and a stubbed call's added wall time. It weighs each router against each tool's p50 by the starting rule, a router p50 under 25% of the tool's, and `--dry-run` prints the calls and cost of a run without making one.
- Routers by name (experimental): `register_router(name, factory)`, `unregister_router(name)` and `available_routers()`, exported from `web_router`, and `router="name"` with `router_config={...}` on `WebRouter` and `AsyncWebRouter`, which builds the router as `factory(**router_config)`. A name nothing is registered under raises `ConfigurationError`, as do `router_config` without a name and a `router_config` key the factory does not take or needs and is not given (the error names the key, never its value; a `TypeError` raised inside the factory itself still propagates). A router built by name is closed with its `WebRouter` (`close()`, or `aclose()` and else `close()` from `AsyncWebRouter`); one passed in stays the caller's. One built and then refused is closed at once; a close that fails then warns with a `ResourceWarning` and the `ConfigurationError` is still raised. A router may name itself in the decision record with a `router_name` attribute. See [A router service](https://docs.webrouter.net/smart-routing#a-router-service).
- The built-in `remote` router (experimental): `WebRouter(router="remote", router_config={"url": ..., "api_key": ..., "timeout_s": ...})` posts each routed call's `RouteRequest` to your router service as JSON and reads its `RouteDecision`, both in the wire format `"schema": 1`. Async only, on one httpx pool kept on the event loop that first used it (a call from another loop gets a client of its own, closed after it; closing the router leaves it closed, and a pool that will not close within 2 s, or whose event loop ended first, is dropped with a `ResourceWarning`: `aclose()` it before its loop ends), so a call past its time (`timeout_s`, 1 s by default, cut to the budget and deadline) is cancelled from sync and async code alike; one request, no retries, no redirects, and no proxy or other setting read from the environment. `https` only, except to `localhost`, 127.0.0.0/8 or `::1`; a URL with credentials, a query or a fragment, or one a browser could read two ways, is refused without being echoed. The bearer key comes from `router_config` or `WEB_ROUTER_REMOTE_ROUTER_API_KEY`, read once, refused unechoed unless it is visible ASCII, and is never logged; no provider key is sent, while the prompt with its URLs whole and the candidate ids, which name the configured backends, are. A timeout is `router_timeout`; a transport error, a non-200 status or a decision naming a `schema` other than 1 is `router_error`; an answer that is not an `application/json` decision within 64 KiB and 64 entries per list or mapping (one held in a method's `params`, such as extract's `urls`, included), `schema` missing included, is `router_invalid`; both leave the static order. Unknown decision fields are ignored, its reasons are cut to 300 characters, and a name it sets (candidate id, provider, option) longer than 128 characters is dropped. The URLs it sets for extract or browse are held to `public_only` when the caller sets no `url_policy` (a router's `min_url_policy` attribute). The decision record names it `remote(<scheme>://<host>)`. A new `remote` extra installs httpx, and `all` includes it.
- The router wire format's JSON Schema, version 1 (experimental): `request.json` and `response.json` under `web_router/data/schemas/router/v1/`, shipped in the wheel and generated from `RouteRequest` and `RouteDecision` with an example each, the same examples the README shows (`uv run python -m web_router.routing.wire_schema`; a test fails when either drifts). `web_router.routing.wire` reads and writes both sides; the response schema holds `confidence` to 0..1 and lets every field be `null`.
- `examples/router_remote_server.py`: a reference router service in the standard library, the wire format around the built-in rules router: it binds 127.0.0.1 (any other host needs the key), answers only a `Host` naming it, checks the bearer key in constant time, caps a request at 1 MB and answers a bad request with a fixed 400 and a router that fails with a 500, neither echoing an error; `--demo` plans three prompts through it offline.
- The MCP server's `WEB_ROUTER_MCP_ROUTER=remote`, with `WEB_ROUTER_REMOTE_ROUTER_URL` and `WEB_ROUTER_REMOTE_ROUTER_API_KEY`, read once from the process environment only (experimental): `web_run` plans through your router service, and the capabilities resource names it `remote(<scheme>://<host>)`, with a `router_note` on what it is sent and a `prompt_note` saying the prompt's URLs go to it whole. The URL and key are captured at startup, so neither a `.env` file, `load_env` nor a later change to the environment moves them, and neither joins the credentials `load_env` loads. See [docs/mcp.md](https://docs.webrouter.net/mcp-server#routing-and-budgets-web_run-budget_start-budget_status).
- route-eval (experimental): each set's report adds, held out, every router's cost-weighted tool confusion matrix -- the tool its choice ran against the best tool, the oracle's, each cell weighed by the dollars and seconds spent beyond the oracle's choice -- with two counts off the oracle, *wrong tool, wrong answer* (accuracy lost to tool choice) and *right, not the cheapest tool* (cost regret), the overspend beside the accuracy lost, and a comparison of each router with `static` and with any router named by the new `--against` (`--against oracle` is refused: the matrix already sets every router against the oracle): where their served paths and tools differ, which alone was right with an exact McNemar p-value, each one's accuracy with its Wilson 95% interval, and mean cost over the questions both costs are known for. A router with no `fit` is also scored and compared on every question. `--json` keeps each router's choices. See the benchmarks README's [Tool confusion and comparing routers](benchmarks/providers/README.md#tool-confusion-and-comparing-routers).
- The MCP server is listed in the official MCP Registry (`server.json`, namespace `io.github.Nimbleway/webrouter`) and on Glama (`glama.json`); `server.json` ships in the source distribution. Each release lists itself in the registry once PyPI has it, from GitHub Actions with no stored token, and the release refuses a tag whose `server.json` names another version.

### Changed

- The sync `WebRouter` warns with a `RuntimeWarning` when it is called on a thread running an event loop, which it blocks; the call still runs. `DeadlineExceededError` from an async `auto` call cut off at its deadline now names, in its message, each backend tried and the one in flight, as the sync path did; it also carries `kind="timeout"`, so a URL an extract lost to the deadline is a `timeout` failure rather than `upstream`. Tavily's SDK clients are built on first use, so the async router no longer builds a sync client it never uses.
- The MCP guide and the agent system prompt are now pages on the docs site, [docs.webrouter.net/mcp-server](https://docs.webrouter.net/mcp-server) and [/agent-prompt](https://docs.webrouter.net/agent-prompt), listed under "Agents and routing", so an agent reading only the site can set up the MCP server. Their sources moved to `docs/mcp-server.mdx` and `docs/agent-prompt.mdx`, and links to the old `docs/mcp.md` now point at the site. The prompt page also says how to install the same contract as an agent skill.
- The MCP server costs a model less context per turn. Its tool list, with every key set, is 26.3 KB of compact JSON (about 6.6k tokens) with search's data API options, down from 31.1 KB (about 7.8k): shorter tool and argument descriptions, and `provider`'s sentence said once in the server instructions instead of on every tool. The new `WEB_ROUTER_MCP_TOOLS` names the tools to list and serve (`search,extract,answer` is about 5.3 KB; a trailing `*` matches a prefix), and a test holds the default list to a budget; `web_run` will not run a method the allowlist leaves out. Results are compact JSON with `None`, `""` and `[]` keys left out. `answer` lists only the sources its answer cites, each with its `marker` (`field` before), and counts the rest in `uncited_sources`, which replaces `citation_count`; `all_sources` lists them all and `snippets` adds each quoted passage. `truncated` now means the main content was cut or an item left out -- a search result's text or a citation's snippet cut to fit is marked where it was cut but no longer sets it -- and its note is shorter. `search_depth` says that unset means the backend's own default. `search`, `extract` and `answer` publish an `outputSchema`, and `resources/templates/list` answers with an empty list.
- The README is now a short landing page: what WebRouter is and why, install, a keyless quickstart, the methods and providers at a glance, routing, budgets, agent use and benchmarking, each linking into the documentation site. Everything it used to hold in detail moved to the docs site, unchanged: the per-method provider tables and the `auto` order to Providers, live data, vendor data, agent integrations, benchmarks and evaluation, smart routing and estimated prices, and adding a provider to pages of their own, and passing keys in code to Configuration. Error messages that pointed at a README table now link to the Providers page.
- **`WebRouter()` and `AsyncWebRouter()` now attach the built-in `rules` router by default** (experimental), and `rules` reads more than URLs. `plan()` and `run()` used to search any prompt with no router; now a prompt with a URL is read with `extract`, one asking in so many words for a report, a comparison or an in-depth analysis ("compare A and B", "write a report on ...", "research ...", "pros and cons of ...") runs `research`, billed per run, or `search` when no research backend is configured, and anything else is searched. It reads English phrases, never single words like "why", "how" or "list", and never picks `browse` or `answer`. It declares `route_tools=()`, so `search()`, `extract()` and every other method you call directly still never ask it. `router=None` attaches no router, as before; `router="rules"` (and `WEB_ROUTER_MCP_ROUTER=rules`) now name it, and `fallback` can list it. The MCP server's `web_run`, which already used `rules`, gains the research rule too, and its description says so.
- **Templates are renamed live data.** `run_template()`, `templates()` and `template()` are now `live_data()`, `live_data_sources()` and `live_data_source()`; `TemplateRequest`, `TemplateResponse`, `Template`, `TemplatePage`, `TemplateSample`, `TemplateProvider` and `TemplateNotFoundError` are `LiveDataRequest`, `LiveDataResponse`, `LiveDataSource`, `LiveDataSourcePage`, `LiveDataSample`, `LiveDataProvider` and `LiveDataSourceNotFoundError`, and the run's `template` field is `source`. The old names still work, with a `DeprecationWarning`, until a later release removes them: imported from `web_router` or from the module they lived in (`web_router.types`, `web_router.registry`, `web_router.exceptions`, `web_router.providers.base`, `web_router.providers.nimble_template`), as a provider's `templates()`/`template()` and their async twins, and as `TemplateNotFoundError(provider, template=...)`. A live data source fetches the site for the call: a backend joins only if it fetches on request (stored datasets are `call_vendor`'s). `LiveDataResponse` gains `records`, every record the run extracted, with `data` kept as the first, and `fetched_at`, the vendor's own fetch time or `None`. **MCP: the tools are renamed with no alias** -- `live_data_sources`, `live_data_source` and `live_data` (its argument `template` is now `source`), and the capabilities resource keys them under `live_data`; a client re-reads the tool list on connect. Their results change keys too: a run returns `records` (every record), `record_count` and `fetched_at` in place of `data`; a listing returns `sources` and `source_count` in place of `templates` and `template_count`; a description returns `source` in place of `template`. The price-list method `run_template` is `live_data`.
- The `evals` extra now accepts `anthropic` 2.x as well as 1.x, and the `browser` extra accepts Playwright 1.64 and 1.65 as well as 1.63; the browser actions were tested on 1.65 against a real Chromium.
- `answer(provider="you", recency="day")` now raises `UnsupportedParameterError` before the call: live, You.com answered it citing pages several days old. `week`, `month` and `year` are unchanged, and the `auto` answer chain moves on to the next backend.
- The MCP server now imports an operator's `WEB_ROUTER_MCP_ROUTER=<module>:<attribute>` router before any `.env` file is loaded, so code that runs when that module is imported sees only the server's own process environment, not a project's `.env` keys. Read anything the router needs from a `.env` file when it is called, not at import. See [docs/mcp.md](https://docs.webrouter.net/mcp-server#routing-and-budgets-web_run-budget_start-budget_status).
- **An error page is a failure, not a document, on every backend.** A page with a status of 400 or more lands in `failures` naming the status, even when it carries text (Jina returned a site's 404 page as a document). A bot challenge (Cloudflare's "Just a moment...", "verify you are human") and a login wall (a "Sign in" page, LinkedIn's `/authwall`) are failures too, so `auto` tries the next backend for them and a call with nothing else raises. A page with under 64 characters of text stays a document but carries a warning in the new `ExtractedDocument.warnings`, which also holds a backend's own warning about the page (Jina's `warning`, which no longer sits in `extra`). See [Extract](https://docs.webrouter.net/extract#error-pages-challenges-and-login-walls).
- Under `auto`, a batch extract that partly fails on one backend sends each URL it failed on to the backends after it in the chain, instead of returning the first backend's partial answer. `response.provider` names the backend that answered first; a URL no backend read stays in `failures` with the reason from each backend that answered for it. A page a backend returns under another address -- a redirect, a login wall -- counts for the URL it was sent for when only one URL could have led there, and is left out when none can be told; `cost_usd` adds each backend that read part of the batch.

## [0.7.0] - 2026-10-26

### Added

- Templates, a sixth method: `WebRouter.run_template(name, inputs, provider=...)` runs one of a vendor's saved, site-specific extractions (Nimble's Extract Templates today) on one page and returns the record it parsed in `TemplateResponse.data`, `templates(provider=...)` lists one page of the vendor's catalogue as a `TemplatePage`, and `template(name, provider=...)` describes one as a `Template` with the JSON Schema of the inputs a run takes and the record it returns; each has its async twin. A template's inputs are its own -- a URL for some, an id, a slug or a search term for others -- which is why this is a method rather than an option on `extract`, and its name belongs to one vendor, which is why `provider` is required and there is no template `auto`. `format` asks for the page beside the record as `markdown` or `html`; unset, no page comes back. A run the backend could not complete, a page the site answered with 4xx or 5xx, or a parse that failed raises `ProviderError` with the reason, never an empty record; an unknown name raises the new `TemplateNotFoundError`. Nimble is the first backend (`NimbleTemplateProvider`, installed by `[extract]`, verified live), with `TemplateProvider` to add another and `register_template_provider()`, `available_template_providers()` and `configured_template_providers()` beside the other registries. The MCP server adds `templates`, `template` and `run_template`, which alone require `provider`, carry handles for `fetch_raw`, and are keyed as `template` in the capabilities resource.
- `contracts/<method>/<provider>.json`: for every provider, the wire fields each option value sends, read from the provider's own code by `make contracts`, beside the vendor's reference pages, where each mapping was verified (live or in the docs) and the vendor's options no mapping sends. CI fails when a contract no longer matches its provider or leaves a hand-written field empty, so a mapping cannot change without its contract. Extract Template backends have one too. [AGENTS.md](AGENTS.md#provider-contracts) says how to start one.
- `max`, an extract provider that sends the request to every backend `auto` would try, all at once, and returns the first document back -- `WebRouter(Provider.MAX).extract(url)`, with `response.provider` naming the backend that answered. Every fetch it starts is billed by its backend, so it costs up to one extract per configured backend per URL -- most backends take one URL per request, and a loser keeps fetching after the winner returns -- and is never the default. Only a document wins: a backend that refused, could not be built or returned nothing is its own loss, and when every one loses the error names each reason. `provider_config={"max": {"hedge": 0.8}}` runs the first member alone for that long and starts the rest only if it has not answered, so most one-URL calls stay at one fetch; a first member that fails early, or answers only part of the list, starts the rest at once. The hedge covers the first member's whole call, so it does not cap the cost of a multi-URL request. The members are `auto`'s: a `chain` or `members_config` set under `"auto"` in `provider_config` applies to `max` too, unless its own `"max"` entry sets one. `format` routes the same way, and the sync router's `close()` waits for a race's losers before shutting their clients while the async router cancels them. `max` joins `auto` in `BENCHMARK_EXCLUDED`, and the MCP `extract` tool offers it under `provider` with its cost in the description.
- `WebRouter.benchmark_extract()` and its async twin: the same URLs fanned out across several extract backends at once, through the public `extract` path, one `ExtractBenchmarkRun` per provider in an `ExtractBenchmarkReport` -- measured facts only, as `benchmark()` reports for search. A backend that fails, cannot return the format, has no credentials or runs out of the comparison's `timeout` (`BENCHMARK_EXTRACT_TIMEOUT`, 120 seconds) is its own row's error, and a call that fetched some URLs and not others is an answered row whose response says which. `BenchmarkRun` and `BenchmarkReport` now share a base with the extract pair; their fields and behaviour are unchanged, except that a row for a backend that could not be built reports a latency of exactly zero on the async router too.
- `benchmarks/providers/extract.py`: every configured extract backend on the same URLs, tabulated per backend (pages returned with text, empty, failed, timed out, refused, latency, median length) and per category, with a suggested `auto` extract order. Two URL sets ship under `benchmarks/providers/urls/` -- `general` (455 URLs) and `social-pdf` (908 URLs), URL lists sampled from public pages -- and `--urls` takes a CSV of your own. The scan writes `run.json` before its first call and each URL's rows as it finishes, so one that dies keeps what it paid for, and `--combine` on that folder alone reports the rows it fetched against the URLs asked. `examples/compare_extract_providers.py` shows the method on one URL.
- `WebRouter.classify()` and `WebRouter.execute()`, an opt-in spike (unchanged unless you pass `decider=`). `classify(query)` asks a decider one set of questions (tool, recent, coverage, well_scoped) and turns the labels into a `Route`: the method and the auto chain to run it on, searching nothing. `execute(route)` runs it. Passing `urls` routes to extract and `output_schema` to research without asking; a decider that fails, or answers below 0.5 confidence, gives today's default, search on the default chain, with `Route.fallback` saying why (`decider_error`, `low_confidence`, `no_url`, `no_backend_for_method`). The decider is swappable: `WebRouter(decider=...)` takes `"keywords"` (simple keyword rules, keyless, with fixed confidences that are not measured; a research or browse pick sits below the threshold, so it falls back to search), `"jev"` (TypeSafe's Jev, reading `TYPESAFE_API_KEY`), `"llm"` (a chat model with structured outputs over any OpenAI-compatible API, with the `evals` extra, taking `api_key=` or reading `OPENAI_API_KEY`; its version carries a hash of its prompt and schema, `gpt-4.1-mini+p<8 hex>`), a name given to `register_decider()`, or any object with `decide()` and `close()`. `decider_config=` passes constructor kwargs to a decider given by name, as `provider_config=` does for backends. Every built-in decider reports confidence on Jev's normalized scale, `(p - 1/n)/(1 - 1/n)` (`normalized_confidence()`), and the llm decider scales its probabilities to sum to 1 before they are checked; an answer it cannot read takes the `decider_error` fallback. A decider that raises anything, not only `ProviderError`, takes the `decider_error` fallback. Exception types a decider names in its `passthrough` attribute propagate instead of becoming a default route.
- Browser Use now maps `output_schema`, `max_steps` and `allowed_domains`, each checked against a live task on 2026-10-21; they were refused before. The schema is sent as Browser Use's `structuredOutput` and the answer comes back as `structured`; an answer that is not JSON stays in `answer`. `auto` can now serve a browse call that sets any of the three, through Browser Use.

## Alpha snapshot - 2026-10-08

The first alpha snapshot, shared with alpha users. Not a published release:
the next published version will be above it.

- **Five methods behind one interface:** `search`, `extract`, `research`
  (agentic, minutes rather than seconds), `open_browser` (a browser session you
  drive, with page actions built in) and `browse` (a hosted browser agent's
  task). Each call behaves the same whichever backend serves it.
- **Many backends,** from Nimble, Tavily, Exa, Brave, Perplexity, Parallel,
  Linkup, You.com, WebIQ, Firecrawl, Oxylabs, Bright Data and Jina Reader to
  Steel, Browserbase, Hyperbrowser, Anchor, Browser Use, Skyvern and a local
  Chromium. Several need no key at all.
- **`auto`,** the default for every method: it tries the backends you hold keys
  for, then the keyless ones, and routes each request to a backend that can
  serve it. Pass a `chain` to choose your own order, per method.
- **An MCP server** (`web-router-mcp`) exposing every method as tools, including
  `browser_*` tools that drive a session, for Claude Code, Claude Desktop,
  Cursor and other MCP clients.
- **Agent integrations:** tools for the Claude and OpenAI APIs, and for
  LangChain, with a routing guide that tells a model which tool fits which need.
- **Benchmarking and evaluation:** `benchmark()` compares backends on the same
  query, `evaluate()` scores their accuracy on a question set with an LLM judge,
  and `benchmarks/` holds the scripts to run both at scale.
