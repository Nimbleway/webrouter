# Changelog

All notable changes to WebRouter are recorded here, newest first. Versions
follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html); while on
`0.x`, a breaking change bumps the minor version.

## [Unreleased]

### Added

- Live data from Apify, Bright Data and Oxylabs: `live_data(provider="apify")` runs an Apify Store Actor (`username~name`) through `run-sync-get-dataset-items` and returns every dataset item as a record; `provider="brightdata"` runs one of Bright Data's ready-made scrapers by its `gd_…` dataset id or its name from Bright Data's catalogue -- `Amazon products` or `amazon_products` collects by URL, `amazon_products_by_keyword` discovers by keyword -- on one input through `/datasets/v3/scrape`; `provider="oxylabs"` runs one of the Oxylabs Web API's dedicated scrapers (`amazon/product`, `google/search`…), listed from its own `GET /v1/scrapers` and described from each endpoint's `OPTIONS`, so its input schema is typed, with required fields, allowed values and defaults; a scraper Oxylabs runs only as a job (`chatgpt`, `gemini`…) is polled for up to five minutes, and any error after its submit is the new `LiveDataJobError`, a `ProviderError` whose `job_id` names the billed job to read later. New: `OXYLABS_WEB_API_KEY`, the Web API's key -- Oxylabs' extract keeps its Realtime username and password. Each lists and describes its catalogue too. Apify and Bright Data were verified live on 2026-11-10; the Oxylabs Web API is written from its docs and not yet verified live. New: `Provider.APIFY` and `APIFY_TOKEN`. A Bright Data scrape that outlasts its synchronous window raises naming the snapshot to fetch; Bright Data's failed inputs land in `extra["errors"]`; a Bright Data name gains its site once another scraper takes the same name, and the not-found error then lists the names that replaced it (the `gd_` id never changes); a description's schemas are `None` where the vendor publishes none.
- `live_data_sources(query=...)` (and the MCP tool's `query`) finds live data sources by keyword, the way each vendor allows: Apify's Store searches itself; Nimble, Bright Data and Oxylabs offer no keyword search over their catalogues, so their catalogues are read whole (up to 5,000 sources) and matched here on name, site, kind of page and description, name and site matches first. `LiveDataSourcePage` gains `query` and `search` (`"native"` or `"local"`). A custom backend opts into native search with the new `NativeSourceSearch` mixin. A local search keeps the catalogue it read for ten minutes, so the next search on that backend reads nothing, and the async router reads the remaining pages concurrently once the first page gives the count.
- Vendor data: `call_vendor()` reaches a vendor's own API with your account's credentials -- your Google Ads reports, your Datadog logs -- and returns the vendor's answer untouched, as a `VendorResponse`. The vendors are a catalog of JSON files in `web_router/data/vendors/`, each written from the vendor's own docs and listed in `VENDORS.md`; `vendors()`, `vendor()`, `vendor_endpoint()` and `find_vendor_endpoints()` look things up in it, and `vendor_request()` calls a path the catalog does not name, still with the vendor's credentials. The router places credentials as each vendor's file says (header or query keys, HTTP Basic, an OAuth refresh token exchanged and cached), reads them from the environment or `vendor_credentials=`, and holds three guarantees: credentials go only to the vendor's own host (no foreign paths, no redirects, region hosts from a fixed list), an undeclared input raises `UnsupportedParameterError` and a missing one `MissingParameterError`, and a write raises `VendorWriteRefusedError` unless `allow_writes=True`. Every credential is masked out of a vendor's error message. New exceptions `VendorNotFoundError` and `VendorWriteRefusedError`; a `vendors` extra (httpx), included in `all` and `mcp`. The MCP server gains `vendors`, `vendor_endpoint` and `call_vendor`; writes there also need `WEB_ROUTER_ALLOW_VENDOR_WRITES=1` at startup, and `load_env` takes every vendor variable. `WEB_ROUTER_VENDOR_CATALOG` names a directory of extra or replacement vendor files. `make vendors` regenerates `VENDORS.md` and `.env.example`'s vendor section. Every entry is checked against the vendor's docs only; none has been called live yet.
- Vendor catalog: 315 vendors and 2,553 endpoints, listed in `VENDORS.md`: ads and analytics accounts (Google Ads, Meta Ads, Google Analytics, Search Console), SEO, social, enrichment and company data, and more: AI model APIs (OpenAI, Anthropic, Mistral, Groq, DeepSeek, xAI), speech and media generation (ElevenLabs, Deepgram, Runway, fal, HeyGen), finance and markets (FRED, SEC EDGAR, sec-api, Financial Modeling Prep, Alpha Vantage, CoinMarketCap, Polymarket, Kalshi), company and people data (ZoomInfo, RocketReach, Clay, BuiltWith, Companies House, GLEIF), public data (the Census Bureau, BLS, EIA, the World Bank, Eurostat, the ECB), weather and maps (Open-Meteo, OpenWeather, Mapbox, Google Maps), messaging (Twilio, SendGrid, Resend) and more. Every entry is written from the vendor's own docs. Some need no key, most of them public data. Vendors were left out when they resell other APIs, publish no API docs, or need what the format cannot express: signed requests (AWS SigV4, HMAC), a host per customer (Zendesk, QuickNode, Unipile) or file uploads. None has been called live yet.
- `DeciderRouter` (experimental), exported from `web_router` with `DeciderQuestion`, `DeciderReply` and `Decider`: a router made of a *decider*, an object with `decide(question)` or `async adecide(question)` that answers one question -- the prompt, the instructions, and each candidate id with its method, backend, estimated cost and p90 latency (extract only when the prompt names a URL) -- with a ranking of option ids, best first, and optional scores and confidence from 0 to 1. Options it leaves out keep the static order. The reply is checked strictly: only offered `str` ids, each once, and finite numbers from 0 to 1; anything else is `router_invalid`. The ranking becomes `tools` and `providers`; it never sets options, exclusions or URLs, and its reason is the decider's name, the first id and its score, never the decider's own words. It declares the decider's `timeout_s`, `name` and `route_tools`, and closes a decider it owns. Register one with `register_router("name", lambda **config: DeciderRouter(MyDecider(**config)))`; `examples/router_decider.py` shows one. See the README's [Decision APIs](README.md#decision-apis-deciderrouter-routerllm-and-routersystemone).
- The built-in `llm` router (experimental): `WebRouter(router="llm", router_config={"preset": ..., "model": ...})`, a chat model on any OpenAI-compatible chat-completions API, posted with httpx and no SDK, so no `OPENAI_BASE_URL` or other variable is read. Presets `openai`, `anthropic` and `openrouter` ask for a strict JSON schema whose enum is the offered ids (a ranking, a score per ranked id as a list of `{"id", "p"}`, and a confidence), `deepseek` and `groq` for JSON mode; a `base_url` of your own asks in the prompt, and needs `api_key_env` unless it is on this machine. `response_format` (`json_schema`, `json_object` or `prompt`) overrides the choice; another value raises `ConfigurationError`. The model's own words are never used. 3 s and research and browse only unless `timeout_s` and `route_tools` say otherwise.
- The built-in `systemone` router (experimental): `WebRouter(router="systemone", router_config={"preset": "typesafe"})`, a System One decision API (TypeSafe's Jev, pinned) asked one `choice` question per call, the prompt and budget as its state, ranking by its probability per option. 1 s and every tool but search unless set.
- Both built-ins send each call's prompt (extract's URLs whole, query strings included), budget and candidate ids with their cost and latency to that server, and nothing is on by default. A preset's key is read once from that vendor's variable and sent only to that vendor's host: naming `OPENAI_API_KEY` or another preset's variable for another `base_url` raises `ConfigurationError`, as does a missing key. They share the `remote` router's transport rules: `https` only (plain `http` to loopback), no credentials, query or fragment in the URL, one request, no retries or redirects, no proxy from the environment, answers of `application/json` under 256 KiB, and failures naming the error class or status and the host, never the URL or key. The record names them `llm(<host>)` and `systemone(<host>)`.
- The built-in `fallback` router (experimental): `WebRouter(router="fallback", router_config={"routers": [...]})` asks a list of routers in order -- each a registered name, a mapping of a `"name"` and that router's config, or a router function or object, sync or async -- until one answers a decision that decides something. A member that times out, raises, answers something other than a decision or answers an empty one is passed over; each keeps its own `timeout_s`, cut to the time left, and the router's own limit is the sum of its members' plus those 20 ms unless `router_config["timeout_s"]` sets it, to more than those 20 ms. When none answers, the call runs on the static order, recorded as `router_empty`, or `router_timeout` when the time ran out first, its members recorded either way, and `fail_on_router_error=True` raises `RouterError` with that code. It stops asking 20 ms before its deadline, so its answer always arrives before the call stops waiting. It sends the prompt to every member it asks, one that times out after receiving it included. The record names it `fallback(<member>, ...)`: a member passed in by its `router_name`, else `custom`, never its import path; `remote` as `remote(<scheme>://<host>)`. Members built by name are closed with it (`close()` and `aclose()`); members passed in are not. See the README's [Chaining routers](README.md#chaining-routers-routerfallback).
- `DecisionRecord.members` and `CompositeDecision` (experimental, public): a router that asks other routers may answer with `CompositeDecision`, a `RouteDecision` subclass with `members`, a tuple of the new `DecisionMember` (`name`, `outcome` -- `ok`, `router_timeout`, `router_error`, `router_invalid` or `router_empty` --, `ms`, `counted`), which the decision record copies to `members`, and `timed_out`, set when no member answered because the time ran out (recorded as `router_timeout`). A decision whose members are not `DecisionMember`s, or name more than one as counted, is `router_invalid`. The wire format reads a plain `RouteDecision`, so a router service cannot set them. `CompositeDecision` and `DecisionMember` are exported from `web_router`.
- The MCP server's `WEB_ROUTER_MCP_ROUTER` names any built-in router, such as `fallback`, configured by the new `WEB_ROUTER_MCP_ROUTER_CONFIG`, a JSON object read once from the process environment (experimental). Each `api_key_env` in it, and the default variable of each `llm` or `systemone` preset given no key (such as `DEEPSEEK_API_KEY`), is read from the process environment at startup, before any `.env` file is loaded, and captured as `api_key`, so neither a project's `.env` file, `load_env` nor a later change to the environment supplies or moves a router's key; a preset's variable unset there stops the server, and a vendor's variable named for a router posting to another host is refused; a value that is not a JSON object, or one set beside no built-in router, stops the server without echoing it. The capabilities resource names each router service's scheme and host in `router_note` and `prompt_note`, a preset's included, and `router` names it as the record will (`llm(api.openai.com)`, `remote(https://host)`), and `router_runs` is `built_in` for a router whose config names no URL. `WEB_ROUTER_MCP_ROUTER=remote` without the new variable reads `WEB_ROUTER_REMOTE_ROUTER_URL` as before. See [docs/mcp.md](docs/mcp.md#routing-and-budgets-web_run-budget_start-budget_status).
- `examples/router_openai_decisions.py` (experimental): OpenAI's Decisions API (`gpt-6-luna`, pinned) as a decider on `DeciderRouter`, one `choice` question per call ranked by its probability per option, 3 s. It sends the prompt to OpenAI and bills one call per plan; tested offline.
- A router may declare its own `route_tools` (experimental): an optional attribute on the router function or object, like `timeout_s`, read when the caller passes `route_tools=None`. The caller's `route_tools` always wins, a router that declares none is still asked on all five tools, and `plan()` and `run()` ask the router whatever it declares; a declaration naming anything else raises `ConfigurationError`. A router built by name declares it too: `router="remote"` takes `route_tools` in `router_config`. From `router_latency.py`'s run, the LLM example router declares `("research", "browse")` and the Jev example every tool but search: at a p50 of 1.2 s and 0.24 s they cost more than a quarter of a search, and the LLM router of an answer too; extract, research and browse are judgement, since they take seconds to minutes. The rules and sklearn examples declare none. See the README's [Smart routing](README.md#smart-routing-experimental).
- `benchmarks/providers/router_latency.py` (experimental): times routers -- the built-in rules, the scikit-learn, LLM and Jev examples, a `remote:<url>` service in the wire format, or your own -- on route-eval's public prompts, interleaved through the library's own router call, with timeouts censored, cold first calls and fresh builds apart, and a stubbed call's added wall time. It weighs each router against each tool's p50 by the starting rule, a router p50 under 25% of the tool's, and `--dry-run` prints the calls and cost of a run without making one.
- Routers by name (experimental): `register_router(name, factory)`, `unregister_router(name)` and `available_routers()`, exported from `web_router`, and `router="name"` with `router_config={...}` on `WebRouter` and `AsyncWebRouter`, which builds the router as `factory(**router_config)`. A name nothing is registered under raises `ConfigurationError`, as do `router_config` without a name and a `router_config` key the factory does not take or needs and is not given (the error names the key, never its value; a `TypeError` raised inside the factory itself still propagates). A router built by name is closed with its `WebRouter` (`close()`, or `aclose()` and else `close()` from `AsyncWebRouter`); one passed in stays the caller's. One built and then refused is closed at once; a close that fails then warns with a `ResourceWarning` and the `ConfigurationError` is still raised. A router may name itself in the decision record with a `router_name` attribute. See the README's [A router service](README.md#a-router-service-routerremote).
- The built-in `remote` router (experimental): `WebRouter(router="remote", router_config={"url": ..., "api_key": ..., "timeout_s": ...})` posts each routed call's `RouteRequest` to your router service as JSON and reads its `RouteDecision`, both in the wire format `"schema": 1`. Async only, on one httpx pool kept on the event loop that first used it (a call from another loop gets a client of its own, closed after it; closing the router leaves it closed, and a pool that will not close within 2 s, or whose event loop ended first, is dropped with a `ResourceWarning`: `aclose()` it before its loop ends), so a call past its time (`timeout_s`, 1 s by default, cut to the budget and deadline) is cancelled from sync and async code alike; one request, no retries, no redirects, and no proxy or other setting read from the environment. `https` only, except to `localhost`, 127.0.0.0/8 or `::1`; a URL with credentials, a query or a fragment, or one a browser could read two ways, is refused without being echoed. The bearer key comes from `router_config` or `WEB_ROUTER_REMOTE_ROUTER_API_KEY`, read once, refused unechoed unless it is visible ASCII, and is never logged; no provider key is sent, while the prompt with its URLs whole and the candidate ids, which name the configured backends, are. A timeout is `router_timeout`; a transport error, a non-200 status or a decision naming a `schema` other than 1 is `router_error`; an answer that is not an `application/json` decision within 64 KiB and 64 entries per list or mapping (one held in a method's `params`, such as extract's `urls`, included), `schema` missing included, is `router_invalid`; both leave the static order. Unknown decision fields are ignored, its reasons are cut to 300 characters, and a name it sets (candidate id, provider, option) longer than 128 characters is dropped. The URLs it sets for extract or browse are held to `public_only` when the caller sets no `url_policy` (a router's `min_url_policy` attribute). The decision record names it `remote(<scheme>://<host>)`. A new `remote` extra installs httpx, and `all` includes it.
- The router wire format's JSON Schema, version 1 (experimental): `request.json` and `response.json` under `web_router/data/schemas/router/v1/`, shipped in the wheel and generated from `RouteRequest` and `RouteDecision` with an example each, the same examples the README shows (`uv run python -m web_router.routing.wire_schema`; a test fails when either drifts). `web_router.routing.wire` reads and writes both sides; the response schema holds `confidence` to 0..1 and lets every field be `null`.
- `examples/router_remote_server.py`: a reference router service in the standard library, the wire format around the built-in rules router: it binds 127.0.0.1 (any other host needs the key), answers only a `Host` naming it, checks the bearer key in constant time, caps a request at 1 MB and answers a bad request with a fixed 400 and a router that fails with a 500, neither echoing an error; `--demo` plans three prompts through it offline.
- The MCP server's `WEB_ROUTER_MCP_ROUTER=remote`, with `WEB_ROUTER_REMOTE_ROUTER_URL` and `WEB_ROUTER_REMOTE_ROUTER_API_KEY`, read once from the process environment only (experimental): `web_run` plans through your router service, and the capabilities resource names it `remote(<scheme>://<host>)`, with a `router_note` on what it is sent and a `prompt_note` saying the prompt's URLs go to it whole. The URL and key are captured at startup, so neither a `.env` file, `load_env` nor a later change to the environment moves them, and neither joins the credentials `load_env` loads. See [docs/mcp.md](docs/mcp.md#routing-and-budgets-web_run-budget_start-budget_status).
- route-eval (experimental): each set's report adds, held out, every router's cost-weighted tool confusion matrix -- the tool its choice ran against the best tool, the oracle's, each cell weighed by the dollars and seconds spent beyond the oracle's choice -- with two counts off the oracle, *wrong tool, wrong answer* (accuracy lost to tool choice) and *right, not the cheapest tool* (cost regret), the overspend beside the accuracy lost, and a comparison of each router with `static` and with any router named by the new `--against` (`--against oracle` is refused: the matrix already sets every router against the oracle): where their served paths and tools differ, which alone was right with an exact McNemar p-value, each one's accuracy with its Wilson 95% interval, and mean cost over the questions both costs are known for. A router with no `fit` is also scored and compared on every question. `--json` keeps each router's choices. See the benchmarks README's [Tool confusion and comparing routers](benchmarks/providers/README.md#tool-confusion-and-comparing-routers).

### Changed

- **Templates are renamed live data.** `run_template()`, `templates()` and `template()` are now `live_data()`, `live_data_sources()` and `live_data_source()`; `TemplateRequest`, `TemplateResponse`, `Template`, `TemplatePage`, `TemplateSample`, `TemplateProvider` and `TemplateNotFoundError` are `LiveDataRequest`, `LiveDataResponse`, `LiveDataSource`, `LiveDataSourcePage`, `LiveDataSample`, `LiveDataProvider` and `LiveDataSourceNotFoundError`, and the run's `template` field is `source`. The old names still work, with a `DeprecationWarning`, until a later release removes them: imported from `web_router` or from the module they lived in (`web_router.types`, `web_router.registry`, `web_router.exceptions`, `web_router.providers.base`, `web_router.providers.nimble_template`), as a provider's `templates()`/`template()` and their async twins, and as `TemplateNotFoundError(provider, template=...)`. A live data source fetches the site for the call: a backend joins only if it fetches on request (stored datasets are `call_vendor`'s). `LiveDataResponse` gains `records`, every record the run extracted, with `data` kept as the first, and `fetched_at`, the vendor's own fetch time or `None`. **MCP: the tools are renamed with no alias** -- `live_data_sources`, `live_data_source` and `live_data` (its argument `template` is now `source`), and the capabilities resource keys them under `live_data`; a client re-reads the tool list on connect. Their results change keys too: a run returns `records` (every record), `record_count` and `fetched_at` in place of `data`; a listing returns `sources` and `source_count` in place of `templates` and `template_count`; a description returns `source` in place of `template`. The price-list method `run_template` is `live_data`.
- The `evals` extra now accepts `anthropic` 2.x as well as 1.x, and the `browser` extra accepts Playwright 1.64 and 1.65 as well as 1.63; the browser actions were tested on 1.65 against a real Chromium.
- `answer(provider="you", recency="day")` now raises `UnsupportedParameterError` before the call: live, You.com answered it citing pages several days old. `week`, `month` and `year` are unchanged, and the `auto` answer chain moves on to the next backend.
- The MCP server now imports an operator's `WEB_ROUTER_MCP_ROUTER=<module>:<attribute>` router before any `.env` file is loaded, so code that runs when that module is imported sees only the server's own process environment, not a project's `.env` keys. Read anything the router needs from a `.env` file when it is called, not at import. See [docs/mcp.md](docs/mcp.md#routing-and-budgets-web_run-budget_start-budget_status).

### Fixed

- The Claude and OpenAI tools' sync `call()` on an `AsyncWebRouter` runs every call on one long-lived event loop instead of a new one each time, so a pool bound to its loop, such as the `remote` router's, is reused rather than dropped with a `ResourceWarning` on every call after the first; called from code with a running event loop, it raises `ConfigurationError` pointing to `acall()` rather than blocking that loop.
- `research(provider="nimble")` no longer cites an `output.sources` entry that has no URL as a citation with an empty `url`.
- Nimble `research` at `effort="max"` runs again. Nimble's API refuses its own `max` tier, which is not open yet, with a 422, so `max` now sends `x-high`, the deepest tier it runs today.
- `research(provider="auto")` no longer starts a second paid run after the first was created. A Nimble connection dropped after the request went out is no longer taken for one that never reached the backend, and a Nimble or Parallel run that finished in the start call but whose answer could not be fetched is returned as running, so the next poll reads it, instead of raised.
- Nimble `research` no longer retries the call that starts a run. The SDK's two retries could create a second billed run after a timeout or a 5xx, and held the call for about three times its timeout.
- `research(provider="perplexity")` and `answer(provider="perplexity")` now also cite the pages the agent opened (`fetch_url_results`), not only the ones its searches found. A page found and opened is cited once.

## [0.12.0] - 2026-11-10

### Changed

- **Breaking (Python version):** WebRouter now requires Python 3.11 or newer. Python 3.10 reached end of life in October 2026, and the fixed releases of some dependencies (Pillow, filelock) no longer support it. On Python 3.10, pip and uv keep installing 0.11.0, the last release that supports it.

## [0.11.0] - 2026-11-09

### Changed

- The repository moved to [github.com/Nimbleway/webrouter](https://github.com/Nimbleway/webrouter). Links to the old location redirect, and the package metadata now points to the new one. Security reports go through GitHub's private vulnerability reporting (see SECURITY.md).
- **Breaking (install name):** the package is now named `webrouter` and is published to [PyPI](https://pypi.org/project/webrouter/): install it with `pip install "webrouter[all]"` or `uv add "webrouter[all]"`. Earlier releases were named `web-router` and published only to a private index. The import is unchanged (`import web_router`), as are the `web-router-mcp` command and the MCP server's name.

## [0.10.0] - 2026-11-09

### Added

- `extract(profile=...)`: a saved identity on the backend whose cookies are sent with each fetch, the same `profile` a browser session starts from, so a login made in a session serves the fetches that follow. `browserbase` is the first extract backend to map it, through a new `BrowserbaseExtractProvider` over the Fetch API (`POST /v1/fetch`, a plain fetch that never renders the page; `markdown` and `html`, the latter Fetch's `raw`), with `profile` sent as `contextId`; it joins extract `auto` and `max` last, after DeepSeek, so no call that was already being served moves. Verified live by hand on 2026-10-29, and by the automated live tests on 2026-11-08: a cookie set in a persisting session came back from a fetch naming the same Context, and from none without it. A backend without saved profiles refuses `profile` rather than fetching anonymously, and extract `auto` and `max` now pass over a member that does not map an option the request sets, as search `auto` does, raising `UnsupportedParameterError` when none is left. The MCP `extract` tool never offers `profile`, as `browser_open` never has.
- web-router is open source under the Apache License 2.0: `LICENSE` at the root, and `license = "Apache-2.0"` in the package metadata.

Costs are list-price estimates, and under a cost cap an unknown price never runs, a price marked as a floor, a request with `provider_options` or a search asking for more results than its price assumes (`results_assumed`) included; the cap holds estimates, not the bill. A router's options are priced on the request the call runs -- `effort`, `search_depth`, `max_results` past `results_assumed`, extract's URLs per page -- and one that does not fit is set aside in `ignored`. A call a backend makes inside a budgeted call, on its own router or another, is reserved once, by the call it is made in, and still settles in the shared budget when it runs in another thread or task or after its parent ended. - `url_policy="public_only"` on `WebRouter` and `AsyncWebRouter` (experimental): a plan or a router does not send a loopback, private or cloud-metadata URL to a backend as a URL (it stays in the prompt text). It resolves no DNS and follows no redirect. Off by default; a URL with no host is refused even then. See [`url_policy`](README.md#url_policy). - Nimble's `samples` moved out of `Template.extra` into the typed `Template.samples`; a caller reading `template.extra["samples"]` reads `template.samples` now.

### Fixed

- An error whose exception has no text -- httpx's read and connect timeouts -- now names its type instead of ending blank: a timed-out answer read `answer failed: ` and now reads `answer failed: ReadTimeout`. The same for every method's wrapped failure and the judge's.

## [0.7.0] - 2026-10-26

### Added

- Templates, a sixth method: `WebRouter.run_template(name, inputs, provider=...)` runs one of a vendor's saved, site-specific extractions (Nimble's Extract Templates today) on one page and returns the record it parsed in `TemplateResponse.data`, `templates(provider=...)` lists one page of the vendor's catalogue as a `TemplatePage`, and `template(name, provider=...)` describes one as a `Template` with the JSON Schema of the inputs a run takes and the record it returns; each has its async twin. A template's inputs are its own -- a URL for some, an id, a slug or a search term for others -- which is why this is a method rather than an option on `extract`, and its name belongs to one vendor, which is why `provider` is required and there is no template `auto`. `format` asks for the page beside the record as `markdown` or `html`; unset, no page comes back. A run the backend could not complete, a page the site answered with 4xx or 5xx, or a parse that failed raises `ProviderError` with the reason, never an empty record; an unknown name raises the new `TemplateNotFoundError`. Nimble is the first backend (`NimbleTemplateProvider`, installed by `[extract]`, verified live), with `TemplateProvider` to add another and `register_template_provider()`, `available_template_providers()` and `configured_template_providers()` beside the other registries. The MCP server adds `templates`, `template` and `run_template`, which alone require `provider`, carry handles for `fetch_raw`, and are keyed as `template` in the capabilities resource.
- `contracts/<method>/<provider>.json`: for every provider, the wire fields each option value sends, read from the provider's own code by `make contracts`, beside the vendor's reference pages, where each mapping was verified (live or in the docs) and the vendor's options no mapping sends. CI fails when a contract no longer matches its provider or leaves a hand-written field empty, so a mapping cannot change without its contract. Extract Template backends have one too. [AGENTS.md](AGENTS.md#provider-contracts) says how to start one.
- `max`, an extract provider that sends the request to every backend `auto` would try, all at once, and returns the first document back -- `WebRouter(Provider.MAX).extract(url)`, with `response.provider` naming the backend that answered. Every fetch it starts is billed by its backend, so it costs up to one extract per configured backend per URL -- most backends take one URL per request, and a loser keeps fetching after the winner returns -- and is never the default. Only a document wins: a backend that refused, could not be built or returned nothing is its own loss, and when every one loses the error names each reason. `provider_config={"max": {"hedge": 0.8}}` runs the first member alone for that long and starts the rest only if it has not answered, so most one-URL calls stay at one fetch; a first member that fails early, or answers only part of the list, starts the rest at once. The hedge covers the first member's whole call, so it does not cap the cost of a multi-URL request. The members are `auto`'s: a `chain` or `members_config` set under `"auto"` in `provider_config` applies to `max` too, unless its own `"max"` entry sets one. `format` routes the same way, and the sync router's `close()` waits for a race's losers before shutting their clients while the async router cancels them. `max` joins `auto` in `BENCHMARK_EXCLUDED`, and the MCP `extract` tool offers it under `provider` with its cost in the description.
- `WebRouter.benchmark_extract()` and its async twin: the same URLs fanned out across several extract backends at once, through the public `extract` path, one `ExtractBenchmarkRun` per provider in an `ExtractBenchmarkReport` -- measured facts only, as `benchmark()` reports for search. A backend that fails, cannot return the format, has no credentials or runs out of the comparison's `timeout` (`BENCHMARK_EXTRACT_TIMEOUT`, 120 seconds) is its own row's error, and a call that fetched some URLs and not others is an answered row whose response says which. `BenchmarkRun` and `BenchmarkReport` now share a base with the extract pair; their fields and behaviour are unchanged, except that a row for a backend that could not be built reports a latency of exactly zero on the async router too.
- `benchmarks/providers/extract.py`: every configured extract backend on the same URLs, tabulated per backend (pages returned with text, empty, failed, timed out, refused, latency, median length) and per category, with a suggested `auto` extract order. Two URL sets ship under `benchmarks/providers/urls/` -- `general` (455 URLs) and `social-pdf` (908 URLs), URL lists sampled from public pages -- and `--urls` takes a CSV of your own. The scan writes `run.json` before its first call and each URL's rows as it finishes, so one that dies keeps what it paid for, and `--combine` on that folder alone reports the rows it fetched against the URLs asked. `examples/compare_extract_providers.py` shows the method on one URL.
- `WebRouter.classify()` and `WebRouter.execute()`, an opt-in spike (unchanged unless you pass `decider=`). `classify(query)` asks a decider one set of questions (tool, recent, coverage, well_scoped) and turns the labels into a `Route`: the method and the auto chain to run it on, searching nothing. `execute(route)` runs it. Passing `urls` routes to extract and `output_schema` to research without asking; a decider that fails, or answers below 0.5 confidence, gives today's default, search on the default chain, with `Route.fallback` saying why (`decider_error`, `low_confidence`, `no_url`, `no_backend_for_method`). The decider is swappable: `WebRouter(decider=...)` takes `"keywords"` (simple keyword rules, keyless, with fixed confidences that are not measured; a research or browse pick sits below the threshold, so it falls back to search), `"jev"` (TypeSafe's Jev, reading `TYPESAFE_API_KEY`), `"llm"` (a chat model with structured outputs over any OpenAI-compatible API, with the `evals` extra, taking `api_key=` or reading `OPENAI_API_KEY`; its version carries a hash of its prompt and schema, `gpt-4.1-mini+p<8 hex>`), a name given to `register_decider()`, or any object with `decide()` and `close()`. `decider_config=` passes constructor kwargs to a decider given by name, as `provider_config=` does for backends. Every built-in decider reports confidence on Jev's normalized scale, `(p - 1/n)/(1 - 1/n)` (`normalized_confidence()`), and the llm decider scales its probabilities to sum to 1 before they are checked; an answer it cannot read takes the `decider_error` fallback. A decider that raises anything, not only `ProviderError`, takes the `decider_error` fallback. Exception types a decider names in its `passthrough` attribute propagate instead of becoming a default route.
- Browser Use now maps `output_schema`, `max_steps` and `allowed_domains`, each checked against a live task on 2026-10-21; they were refused before. The schema is sent as Browser Use's `structuredOutput` and the answer comes back as `structured`; an answer that is not JSON stays in `answer`. `auto` can now serve a browse call that sets any of the three, through Browser Use.

## Alpha snapshot - 2026-10-08

The first alpha snapshot, shared with alpha users. Not a published release:
the next published version will be above it.

- **Five methods behind one interface:** `search`, `extract`, `research`
  (agentic, minutes rather than seconds), `open_browser` (a browser session you
  drive, with page actions built in) and `browse` (a hosted browser agent's
  task). Each call behaves the same whichever backend serves it.
- **Many backends,** from Nimble, Tavily, Exa, Brave, Perplexity, Parallel,
  Linkup, You.com, WebIQ, Firecrawl, Oxylabs, Bright Data and Jina Reader to
  Steel, Browserbase, Hyperbrowser, Anchor, Browser Use, Skyvern and a local
  Chromium. Several need no key at all.
- **`auto`,** the default for every method: it tries the backends you hold keys
  for, then the keyless ones, and routes each request to a backend that can
  serve it. Pass a `chain` to choose your own order, per method.
- **An MCP server** (`web-router-mcp`) exposing every method as tools, including
  `browser_*` tools that drive a session, for Claude Code, Claude Desktop,
  Cursor and other MCP clients.
- **Agent integrations:** tools for the Claude and OpenAI APIs, and for
  LangChain, with a routing guide that tells a model which tool fits which need.
- **Benchmarking and evaluation:** `benchmark()` compares backends on the same
  query, `evaluate()` scores their accuracy on a question set with an LLM judge,
  and `benchmarks/` holds the scripts to run both at scale.
