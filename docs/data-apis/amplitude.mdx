## Setup

| Variable | | What it is |
|---|---|---|
| `AMPLITUDE_API_KEY` | required | the project's API key (Organization settings &gt; Projects &gt; the project), the Basic auth username |
| `AMPLITUDE_SECRET_KEY` | required | the same project's secret key, the Basic auth password |
| `AMPLITUDE_HOST` | optional | amplitude.com for US projects, analytics.eu.amplitude.com for EU data residency. Default `amplitude.com`. One of `amplitude.com`, `analytics.eu.amplitude.com`. |

Put them in your environment or `.env`; [Data APIs](/vendors) covers the other ways.

## Notes

- Keys belong to one project: every call reads that project only.
- Dates are YYYYMMDD without dashes; times follow the project's time zone. Event and property names with spaces must be URL encoded (the client does this).
- Limits: 5 concurrent requests per key. Queries also spend a per-project cost budget (1,000 concurrent, 108,000 per hour): cost = days x conditions x query-type cost, at least 10, with ranges under 7 days counted as 7. 429 when exceeded; honour Retry-After.
- Events (e, e2, se, re) are JSON objects &#123;event_type, filters, group_by&#125;; filters are [&#123;subprop_type: event|user, subprop_key, subprop_op, subprop_value: [..]&#125;] with ops is, is not, contains, does not contain, less, greater, set is, ... Custom user properties take a gp: prefix.
