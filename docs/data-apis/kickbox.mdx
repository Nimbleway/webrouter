## Setup

| Variable | | What it is |
|---|---|---|
| `KICKBOX_API_KEY` | required | A Kickbox API key (app.kickbox.com &gt; API Keys &gt; Add). Sent as a Bearer token; the apikey query parameter also works. |
| `KICKBOX_API_HOST` | optional | API host: the default, or api.eu.kickbox.com for an EU-only account (one that signs in at app.eu.kickbox.com). Default `api.kickbox.com`. One of `api.kickbox.com`, `api.eu.kickbox.com`. |

Put them in your environment or `.env`; [Data APIs](/vendors) covers the other ways.

## Notes

- Up to 25 parallel requests per IP and 8,000 requests per clock minute; a 429 can be retried at once.
- Each response carries X-Kickbox-Balance (verification credits left) and X-Kickbox-Response-Time headers.
- A sandbox key verifies without using credits and returns mock results (deliverable unless the address names another outcome, such as rejected-email@example.com); a key is created as sandbox or production and cannot switch.

<Note>
- Uses a verification credit. Reasons: invalid_email, invalid_domain, rejected_email, accepted_email, low_quality, low_deliverability, no_connect, timeout, invalid_smtp, unavailable_smtp, unexpected_error.
- An unknown result means the mail server did not answer in time; retrying after about 5 minutes often resolves it.
- success false with a message (invalid API key, balance depleted, rate limit exceeded) is a request failure, not a verification result.
</Note>
