## Setup

| Variable | | What it is |
|---|---|---|
| `DD_API_KEY` | required | a Datadog API key (Organization Settings &gt; API Keys) |
| `DD_APPLICATION_KEY` | required | a Datadog application key (Organization Settings &gt; Application Keys); reads act with its owner's permissions |
| `DD_SITE` | optional | Your Datadog site, the host your app runs on without 'app.': datadoghq.eu for app.datadoghq.eu. A key only works on the site it was created on. Default `datadoghq.com`. One of `datadoghq.com`, `us3.datadoghq.com`, `us5.datadoghq.com`, `datadoghq.eu`, `ap1.datadoghq.com`, `ap2.datadoghq.com`, `uk1.datadoghq.com`, `ddog-gov.com`, `us2.ddog-gov.com`. |

Put them in your environment or `.env`; [Data APIs](/vendors) covers the other ways.

## Notes

- Every read needs both keys: the API key identifies the organization, the application key the user whose permissions apply. A scoped application key without the endpoint's permission answers 403.
- Time units differ by API: v1 metric queries take epoch SECONDS and answer in epoch MILLISECONDS; v2 logs and events take date math ('now-15m') or millisecond timestamps.
- Pagination differs by API: v2 endpoints return meta.page.after (or links.next) as a cursor to send back as page[cursor]; v1 endpoints page by number.
- Datadog also accepts 'Authorization: Bearer' personal or service access tokens; this entry uses the API and application key pair, which every endpoint accepts.
