## Setup

| Variable | | What it is |
|---|---|---|
| `HLRLOOKUP_API_KEY` | required | your hlrlookup.com API key (account &gt; API settings) |
| `HLRLOOKUP_API_SECRET` | required | the API secret paired with that key |

Put them in your environment or `.env`; [Data APIs](/vendors) covers the other ways.

## Notes

- hlrlookup.com, not the different provider hlr-lookups.com.
- Every call is a POST with a JSON body; the credentials travel in that body (this entry adds them).
- Send one number as telephone_number, or up to 80 in requests; more than 80 is a BAD_REQUEST.
- 429 Too many requests means the API is busy; back off and retry.
- Non-200 responses and per-result errors such as INSUFFICIENT_CREDIT, BAD_FORMAT and NO_COVERAGE are not charged.

<Note>

- The response is always &#123;results: [...]&#125;; each item has error 'NONE' or its own error, e.g. TOO_MANY_REQUESTS for one throttled item in a batch.
- Whether a new result is stored in hlrlookup's cache follows the account's own cache setting; the save_to_cache option is left out because it can write to the cache shared by every hlrlookup user.
</Note>
